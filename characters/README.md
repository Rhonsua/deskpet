# 自定义角色：放入素材即可切换

## 使用方法

1. 在桌宠“设置 → 更多设置 → 角色外观”点击“打开角色文件夹”。也可右键桌宠 → 设置 → 更多设置进入。
2. 在打开的目录中，为每个角色新建一个独立子文件夹，放入至少一张透明 `idle.png`。
3. 点击“刷新角色”，在“角色外观”下拉框选择该角色，即时切换，无需重启。

源码运行时使用项目的 `characters/`。0.3.0 及之后的打包版本使用 `%LOCALAPPDATA%\TianyiPet\characters`，避免更新程序时覆盖用户角色；以“打开角色文件夹”实际打开的位置为准。0.3.0 安装包包含角色切换；角色包单独安装，不内置第三方角色。

切换会保存，下次启动恢复所选角色。音乐、听歌记录、等级和音符共用，不会因换角色清空，也没有为每个角色建立独立存档。添加或编辑素材后再次点击“刷新角色”，会重新加载当前角色，不使用旧图片缓存。删除或损坏当前角色时，运行中的桌宠保留最后成功加载的图片；下次启动加载失败则恢复内置精致版洛天依，并在设置中说明原因。下拉框可切回 Live2D 洛天依或静态精致版洛天依；缺少 Live2D 素材时会提示并回退。

## 最简角色包：只需要 PNG

```text
characters/
  我的角色/
    idle.png             # 唯一必需的图片
    personality.json     # 可选：文字聊天人格
    character.json       # 可选：图片配置与显示名称
    blink.png            # 以下均可选
    happy.png
    eat.png
    lift.png
    sleep.png
    phone.png
    sing-front.png
    sing-left.png
    sing-right.png
```

没有配置文件时，程序以文件夹名作为角色名，自动读取上述文件，使用默认头部与落地锚点。角色文件夹必须直接位于角色目录下，不会递归查找第二层角色包；每次最多扫描 128 个角色包。角色目录内的 `README.md` 和只有配置模板的 `example/` 不会被当成角色。

## 美术素材要求

- **格式**：单张、带真实透明背景的 PNG，建议 RGBA。不要把棋盘格、白底、黑底画进图片。完全透明空图和完全不透明图片会被拒绝。
- **画布**：推荐所有动作统一使用 **512×512**；也可使用其他尺寸或长方形画布，但同一角色的全部动作必须宽高一致。
- **摆放**：保留画布透明边距，主体尽量占画布的 60%～90%，不要贴边。所有动作使用同一坐标系、相近角色比例与统一落地点，程序保留整张画布，不会逐动作自动裁边。
- **锚点**：默认头部中心 `[0.5, 0.28]`，默认落地点 `[0.5, 0.98]`。坐标相对整张原图，左上角 `[0, 0]`、右下角 `[1, 1]`。头部应在落地点上方；复杂体型请通过配置调整。
- **落地点**：站姿通常是双脚接地中心；睡觉或玩手机时，用被子或身体接地中心对齐同一位置。并非所有动作都要画成站姿。自定义角色各动作使用同一缩放比例，避免切换时忽大忽小。
- **头部**：头部锚点用于摸头区域、探头中心及从边缘拖出的定位。周围椭圆范围用于区分摸头和戳身体，透明区域仍不接收角色点击。当前每个角色共用一组锚点，建议先以待机图校准。
- **资源限制**：单张不超过 4096×4096、16 MiB；一个角色包的不同图片合计不超过 `16 × 1024 × 1024` 像素（解码像素约 64 MiB，另有显示缓存）。建议控制在 10 张 512×512 图片左右。

### 动作表与缺图回退

| 文件名 / `states` 名称 | 触发与建议画面 | 缺失时 |
| --- | --- | --- |
| `idle.png` / `idle` | 常规待机、陪伴听歌，角色全身 | 必需，不能缺失 |
| `blink.png` / `blink` | 待机眨眼，其他位置与待机一致 | `idle` |
| `happy.png` / `happy` | 摸头、开心、起床回应 | `idle` |
| `eat.png` / `eat` | 投喂，建议画出持有的食物 | `idle` |
| `lift.png` / `lift` | 提起、戳身体的惊讶姿势 | `idle` |
| `sleep.png` / `sleep` | 睡眠，建议完整画出枕头或被子 | `idle` |
| `phone.png` / `phone` | 玩手机，建议完整画出手机及被子 | `idle` |
| `sing-front.png` / `sing-front` | 正面唱歌，麦克风需要画在图中 | `idle` |
| `sing-left.png` / `sing-left` | 左侧转唱歌，比例与正面一致 | 优先 `sing-front`，再 `idle` |
| `sing-right.png` / `sing-right` | 右侧转唱歌，比例与正面一致 | 优先 `sing-front`，再 `idle` |

每张图是一幅完整姿势，不是局部替换层。提供一张 `idle.png` 就能使用拖拽、互动、探头、呼吸和轻摆等程序动画；提供对应动作图后，才会出现眨眼、被子、麦克风和侧转造型。缺图不会借用内置洛天依的身体或道具。

本目录接口支持静态姿势图、程序动画，以及通过 `walk` 明确声明的左右散步 PNG 序列帧。**暂不支持 GIF、APNG 动画、未声明的序列帧目录、精灵图切片、外部 Live2D 或骨骼模型**。内置“Live2D 洛天依”为单独的源码实验功能，不通过本目录格式加载。PNG 即使包含 APNG 帧也只按单张姿势使用。外部角色默认不启用腿部形变；有合适唱歌图的角色包可按下文显式开启。手机位置光效仍只作用于内置洛天依，避免出现悬空光效。持续状态与临时动作规则通用，例如睡觉 → 拖动 → 松手仍回到睡觉。

## 可选配置：名称、作者、动作路径和锚点

需要自定义显示名称、锚点或图片路径时，将 `example/character.json.example` 复制到自己的角色文件夹，改名为 `character.json`。使用 UTF-8 编码保存，支持 Windows 记事本产生的 UTF-8 BOM。

```json
{
  "version": 1,
  "id": "my-character",
  "name": "我的角色",
  "author": "素材作者",
  "source": "素材来源链接及授权说明",
  "states": {
    "idle": "idle.png",
    "blink": "blink.png",
    "sing-front": "sing-front.png"
  },
  "anchors": {
    "head": [0.5, 0.28],
    "feet": [0.5, 0.98]
  }
}
```

示例中的可选图片若未准备好，请删除对应的 `states` 项。**有配置文件时，只有 `states` 和可选 `walk` 明确列出的图片会加载**，不会再自动添加同目录的其他图片。可以使用 `states/idle.png` 等子目录相对路径；拒绝绝对路径、目录越界，以及指向角色目录外的符号链接。

| 字段 | 要求 |
| --- | --- |
| `version` | 固定为整数 `1` |
| `id` | 小写字母开头，后接小写字母、数字、`_` 或 `-`，总长不超过 64 |
| `name` | 非空显示名称，最多 80 字符；目录名可使用中文 |
| `author` / `source` | 可选，最多 120 / 500 字符；当前角色的作者、来源和授权说明会显示在设置中 |
| `states` | 必须包含 `idle`；只接受上方动作表中的名称；被声明的每张图都必须存在且通过校验 |
| `anchors` | 可选 `head` / `feet`，每项为两个 0～1 的数值，头部纵坐标小于落地点纵坐标 |
| `walk` | 可选左右散步 PNG 序列，见下文；省略时不提供散步能力 |
| `singing_motion` | 可选唱歌腿部动画配置，见下节；省略时外部角色不进行腿部形变 |

配置文件最多 64 KiB。配置中不能放可执行脚本，不会自动访问 `source` 链接或下载素材。角色素材应由提供者确认使用权限并保留原作者及授权说明，项目代码的 MIT 许可证不代表对外部素材的授权。

### 可选唱歌腿部动画

本功能需要支持 `singing_motion` 的新版主程序；此前发布的 0.4.2 安装包可以正常加载带此字段的角色包，但会忽略这个字段，仅显示原有姿势切换和整图动画，不启用外部角色的腿部形变。旧角色包无需修改，默认行为不变。在 `character.json` 顶层增加：

```json
"singing_motion": {
  "legs": true,
  "hem": 0.65
}
```

- `legs` 只能为 `true` 或 `false`，默认 `false`。开启时必须在 `states` 明确提供 `sing-front`；左右唱歌图仍可省略并回退正面图。
- `hem` 为腿部形变起始线，相对**整个画布高度**从上向下计算，范围 `0.35`～`0.90`，默认 `0.64`。例如 1024 像素高画布中的 `0.65` 约对应第 666 像素。它应位于裙摆下方、两条腿开始分离的位置，不是角色自身包围框的比例。
- 三张唱歌图须统一画布、角色尺寸、裙摆高度和落地点；`hem` 以下应仅包含两条清晰分开的腿。长发、衣摆、手臂、麦克风等若伸到这条线下，也会被当作腿部移动；这种素材应提高这些部位的位置、调整起始线或关闭本功能。
- 程序保持头身及麦克风完整，腿部轻摆和交替抬脚；有已分析的节拍时跟随节拍。朝向切换只显示当前一张姿势，不叠加淡入淡出，因此不会产生两个人物同时出现的转向虚影。
- 这仍是单图局部形变，不是骨骼模型。`head` / `feet` 继续使用同一套角色锚点；所有动作请保持相近的头部位置与共同落地点。

`singing_motion` 只接受 `legs` 和 `hem`，错误类型、越界比例或缺失必要唱歌图会使该角色包加载失败，并保留之前正常显示的角色。

## 可选散步序列帧

此接口需要含散步支持的新版源码，旧安装包会忽略 `walk`；旧角色包无需补文件，不会因为缺少散步素材而拿站姿平移。示例模板见 [character-walk.json.example](example/character-walk.json.example)。在 `character.json` 顶层增加：

```json
"walk": {
  "left": ["walk/left/000.png", "walk/left/001.png", "walk/left/002.png", "walk/left/003.png"],
  "right": ["walk/right/000.png", "walk/right/001.png", "walk/right/002.png", "walk/right/003.png"],
  "fps": 4,
  "stride": 128
}
```

- `left`、`right` 为左右方向完整人物的 PNG 路径列表，按播放顺序填写。每侧 2～48 帧、至少两个不同文件，两侧帧数必须一致。可以复用列表中的帧实现停留，但不能只列同一张站姿。不会自动镜像：衣服、长袜、配饰不对称的角色应分别绘制左右素材。
- `fps` 为每秒序列帧数，范围 1～30；完整双步周期 = 每侧帧数 ÷ `fps`。例中 4 帧 / 4 fps = 1 秒。末帧之后直接循环到首帧，避免额外重复首帧造成停顿。
- `stride` 为**一个完整双步周期在源图片画布坐标中前进的像素数**，范围 1～4096。实际每秒移动距离 = `stride ÷ 周期秒数 × 显示缩放`。例如源画布高 768，显示高 270，`stride: 128` 对应每周期前进 45 个 Qt 逻辑像素。调节步幅应配合支撑脚位移，避免滑步。
- 序列帧与 `states` 的姿势图必须同一画布大小，使用同一 `anchors.head`、`anchors.feet`。保留完整透明画布，不逐帧裁边；脚底和人物大小应稳定。每帧包含完整人物，不能把腿、手等部件单独作为一帧，也不能画入阴影外的背景。
- 帧图与姿势图共用原有资源限制：每张最大 4096×4096 / 16 MiB，所有不同文件解码合计最多 `16 × 1024 × 1024` 像素（约 64 MiB RGBA，不含显示缓存）；重复路径只计一次。推荐每侧 4～8 帧、512×512 或类似大小，不要为大量帧使用超大画布。
- `walk` 必须且只能包含上面四个字段。路径逃出角色目录、文件缺失、无透明通道、空白帧、画布不一致、超出限制或只有一侧都会拒绝该角色包；切换失败保留先前正常角色。缺少 `walk` 则正常加载其余动作，散步功能不可用。

散步是独立的临时状态，结束或被点击、拖动、右键、工具窗口、新状态打断后取消路线，保存的待机／休息等状态不被改写。自动散步只在合适的空闲条件下随机触发，成功开始后至少冷却 600 秒；中断不清冷却。手动散步可绕过自动冷却，但不改动它。角色切换不会重置自动冷却。

### 与后续 Live2D 的兼容约定

移动层只依赖一个循环的 `cycle_seconds` 和同坐标系的 `stride`，输出左右方向及循环经过时间；静态渲染层据此选择单张帧图，后续 Live2D 可用同一时间采样左右步行动作。显示缩放由各自渲染层提供，移动层不读取 PNG、不翻转模型，也不修改 Cubism 参数。

当前 `character.json` 的 `walk` 仅声明 PNG 资源，不能把 `.motion3.json` 填进帧路径。外部 Live2D 角色加载和具体动作绑定仍需后续实现；模型未提供左右步行动作时不会凭空启用移动。内置静态洛天依使用独立的 `assets/character/walk/walk.json`（相同四字段，路径相对该文件目录），避免旧内置姿势图的历史裁切影响序列帧画布。

内置 Live2D 加载器现已支持 `action-map.json` 中的可选声明：

```json
"walk": {"left": "WalkLeft", "right": "WalkRight", "stride": 64}
```

左右名称对应 `.model3.json` 的 `FileReferences.Motions` 中两个不同的专用动作组。动作必须为相同周期的循环（0.2～10 秒），当前读取器仅支持线性／阶梯曲线。`stride` 的单位是当前 384×576 渲染画布中的像素，每循环移动距离会乘 `.5 × 桌宠缩放`。所有曲线参数需登记在 `integrationRules.resetParameters` 中，动作需明确声明全部姿态组的部件显隐，模型本身必须含有曲线引用的参数与部件。缺少或无效的可选动作只关闭散步，不影响原模型待机。当前内置模型尚未提供这些步行动作，此合同用于后续 Cubism 接入，不会让现有模型原地站姿滑动。

## 可选人格接口：personality.json

人格插件是角色文件夹里的一个可选 JSON 文件，与图片配置相互独立。旧的纯 PNG 角色包仍可正常使用；外部角色没有人格文件时使用通用陪伴人格，不会借用洛天依身份。格式错误或读取失败时也回退，并在聊天界面提示。

复制 [通用人格模板](example/personality.json.example) 到自己的角色目录，改名为 `personality.json`，用 UTF-8 保存（支持 BOM）。可参考 [洛天依人格资料](../docs/洛天依人格资料与插件.md)。初音未来的独立模板在 [pet_chat/personas/miku.json](../pet_chat/personas/miku.json)，使用时也须复制到自己的角色目录并改名；仅修改角色显示名称或 `id` 不会自动绑定这份模板。背景与创作区别见 [初音未来人格资料](../docs/初音未来人格资料.md)。

```text
characters/
  我的角色/
    idle.png
    character.json       # 可选的图片配置
    personality.json     # 可选的聊天人格，固定文件名
```

| 字段或限制 | 要求 |
| --- | --- |
| 顶层字段 | 必须且只能有 `version`、`id`、`name`、`persona`、`scope`、`examples` |
| `version` | 整数 `1` |
| `id` / `name` | 各为非空字符串，最多 100 字符；仅为人格标识与名称，不决定角色绑定 |
| `persona` | 非空人格正文，最多 8000 字符；建议明确身份、性格、说话方式和陪伴边界 |
| `scope` | 必须且只能有 `allowed`、`decline`、`guidance` |
| `allowed` / `decline` | 各为 1～32 项非空字符串，每项最多 300 字符，描述擅长及不承接的任务 |
| `guidance` | 非空字符串，最多 2000 字符，说明越界时如何自然回应 |
| `examples` | 0～12 组示例，每组必须且只能有 `user`、`assistant`；各为非空字符串，最多 1000 字符 |
| 总量 | 文件最多 64 KiB；上述所有字符串合计最多 16000 字符 |
| JSON 校验 | 拒绝重复字段、未知字段、非法编码和非标准数值；路径不得越出角色目录 |

人格在聊天首次关联角色或切换到另一个角色时读取。编辑文件后，切到其他角色再切回，或重新启动程序；刷新图片不保证重新读取同一角色的人格。已有保存的人设和未保存的编辑草稿会保留，默认文件不会自动覆盖它们。需要更新正文时，在聊天的人设页点击“套用角色默认人设”，检查后保存；套用可用 Ctrl+Z 撤销，记忆保持不变。聊天历史、编辑人设与记忆按角色文件夹分别保存，改显示名不会新建身份，移动或重命名文件夹可能改变对应身份。音乐和成长仍共用。

插件只描述数据，不执行脚本、不安装依赖、不访问其中的链接。它用于文字聊天，不会生成语音或获得电脑操作权限。程序的陪伴范围仍限制复杂解题、考试代答、编程与专业任务，不能靠修改 `persona`、`scope` 或示例解除；写成“万能助手”也不会获得相应能力。对工作和作业的倾诉仍可正常陪聊，简单常识和算数也不应故意答错。

## 检查与常见问题

- **列表里找不到**：确认目录是 `characters/我的角色/idle.png`，而不是多套了一层文件夹；点“刷新角色”。
- **文件名看起来正确却报缺失**：在资源管理器显示文件扩展名，避免 `idle.png.png` 或 `character.json.txt`。
- **点选后仍是旧角色**：查看设置下方“角色加载失败”的具体原因。坏包不会替换当前角色，也不会清空数据。
- **动作跳位或大小突变**：检查所有图片的画布尺寸、人物比例与落地点是否一致；不要单独裁剪某个动作的透明边缘。
- **摸头或探头位置不对**：调整头部锚点；落地位置不对则调整 `feet`，修改后点“刷新角色”。
- **没有睡觉或唱歌造型**：需要补充对应姿势图；程序不会凭一张待机图生成新衣服、被子或麦克风。

可在项目根目录运行校验器，只检查文件，不启用角色、不修改素材：

```powershell
.\.venv\Scripts\python.exe character_packs.py "characters/我的角色"
```

开发接口位于 `character_packs.py`：`discover_packs(root)` 按需扫描配置；`read_pack(folder)` 读取配置或推断约定文件名；`validate_images(pack)` 校验并返回解码图片；`pack.state_path(action)` 解析动作回退。启动只解码当前选中的外部角色，不批量解码全部角色；打开设置或点击刷新时再扫描候选包。
