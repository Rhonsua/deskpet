# Live2D 提起害怕闭眼与挥臂增强方案

记录日期：2026-10-23。2026-10-24 已实现并启用到源码运行资源；模型导出、Viewer 循环、自动测试及真实短距离拖放已验证。持续长按、多屏与不同系统缩放的完整人工验收仍待补充；安装包未重打。

## 目标效果

角色被鼠标托起／拎起时，表现为突然失去支撑的小慌张：紧闭双眼、眉毛紧张、小幅张嘴，双臂明显上下扑腾。身体保留拖拽惯性，头发稍有滞后。鼠标不动但仍按住时，动作也继续播放。

双臂运动是主要视觉反馈，不能仅靠整个人上下抖动来代替。表情应区别于摸摸时的开心闭眼；不增加真实恐惧数值、惩罚或音符扣除。本期不增加气泡和语音。

## 相似实现与取舍

### 首选参考：Shimeji-ee 的 Dragged / Resisting

已阅读项目原始动作配置：[gil/shimeji-ee — actions.xml](https://github.com/gil/shimeji-ee/blob/master/conf/actions.xml#L233-L310)。

- `Dragged` 是循环序列，依次运行 `Pinched` 和 `Resisting`。
- `Pinched` 按脚部与光标的水平偏移选择不同倾斜姿势。
- `Resisting` 交替播放两张挣扎帧，中间穿插停顿，后段加快切换。

借鉴其“被提起 → 扑腾 → 短暂停顿 → 继续扑腾”的节奏，以及身体倾斜与挣扎分开处理的结构。此处确认的是代码与配置逻辑，没有实际运行它；也没有确认其素材包含害怕闭眼或与天依一致的手臂造型。我们自行制作天依的表情和连续挥臂，不直接引入该项目素材。

辅助参考：[VPet 的 Main.xaml.cs](https://github.com/LorisYounger/VPet/blob/main/VPet-Simulator.Core/Display/Main.xaml.cs)。其抬起交互区触发 `DisplayRaised`，移动时围绕配置的抬起点调整窗口，松手或失去捕获进入 `DisplayRaising`。可借鉴抓取、移动、释放的生命周期；本项目继续沿用已有拖拽位置逻辑，不照搬对方窗口控制。

参数合成依据：[Live2D 官方 Parameter Operation](https://docs.live2d.com/en/cubism-sdk-manual/parameters/)。该文展示表情与眨眼的更新顺序会改变最终眼睛开合。实施时必须明确提起表情的覆盖顺序，避免闭眼被其他动作重置。

以上为参考已确认内容；下面的时间、幅度和参数设计均为本项目拟定值，需要预览调校。

## 动画分段

| 阶段 | 建议时长 | 表现 |
| --- | --- | --- |
| 刚提起 | 0.12～0.18 秒 | 快速闭眼，眉毛收紧，肩膀抬起，双手开始上举；过渡连续 |
| 空中保持 | 持续到松手 | 约每秒 2～2.5 次上下挥臂；每扑腾 2～3 次短暂停顿 0.2～0.35 秒，再继续；始终闭眼 |
| 放下 | 沿用现有 0.65 秒落地阶段 | 立即停止循环，在前 0.2～0.3 秒收手、放松眉毛，随后回到原有状态 |

双臂大致同步，允许约 0.05 秒的轻微错峰；不要完全反相成左右招手。肘部微弯、手掌跟随前臂，袖口有少量滞后。身体摇摆幅度应明显小于手臂运动，抓取点保持稳定。

## 当前项目基础与限制

- `pet_behavior.py` 已将保存状态 `mode` 与过程动作 `layers` 分开：`begin_drag()` 压入 `lift`，`end_drag()` 移除并可接 `land`；应继续使用这条链路。
- `desktop_pet.py` 已有 `begin_drag()`、`drag_to()`、`interaction_transform()` 和松手逻辑；`drag_motion.py` 提供拖动惯性。边界停靠时存在显示与结束拖动的特殊分支，需要单独验证。
- `live2d_motion.py` 将 `lift` 映射为 `Lift`，使用本项目自己的动作时钟采样。当前 `motions/lift.motion3.json` 是 2.4 秒循环。
- `live2d_renderer.py` 先采样动作，再叠加鼠标跟随及摸摸反馈；SDK 自动眨眼已关闭。提起期间应继续排除摸摸和视线跟随的干扰。
- 当前模型具有眼开合、眼笑、眉毛及 `ParamArmLSwing` / `ParamArmRSwing` 参数。`action-map.json` 的肩部配置显示：现有手臂参数范围 ±30，只对应约 ±4° 的旋转，并服务于其他动作。不能把参数名称中的数值直接当作实际转角。

因此，大幅挥臂需要先检查并补做 Cubism 绑定，不能只扩大现有参数输入或全局修改肩部幅度，以免破坏唱歌、招手等动作。

## 拟实施方式

1. 从当前有效的 `experiments/live2d-tianyi/headpat-model/tianyi-headpat.cmo3` 另存候选工程，并备份运行模型。保留摸摸参数和现有全部动作。
2. 制作专用紧张闭眼形态：优先检查现有眼开合与眉毛组合；若只能得到开心／睡觉闭眼，则新增 `ParamLiftFear`（拟定名，0～1）。默认 0 时必须恢复现有形态。
3. 为左右手臂增加独立的提起动作参数，例如 `ParamLiftArmL`、`ParamLiftArmR`（拟定名，0～1）。分别制作下、中、上三个关键形态；建议先预览约 20～35° 的可见肩臂摆幅，再按袖口、头发遮挡调小。必要时补肘部变形及原画缺失区域。
4. 挥臂使用同一组连续变形的手臂。明确关闭麦克风、招手等互斥姿势部件，避免两条手臂重影；不靠不同完整姿势半透明叠加制造运动。
5. 动作组织为开始、循环、释放三段，挂在现有 `lift` / `land` 过程状态下。记录释放瞬间的臂位与表情，平滑回收；当前采样器不会自动执行 motion 文件里的淡入淡出元数据，必须显式处理过渡。
6. Cubism 导出的贝塞尔曲线需预采样为当前 `Curve` 支持的线性或阶梯段；不能直接交付一个采样器不支持的动作文件。
7. 若新增参数由运行层叠加驱动，必须加入统一重置集合，默认全部为 0。提起表情在参数合成中的优先级要覆盖其他眼睛表情；释放后不得残留闭眼、举手或麦克风隐藏。

## 保存状态与边界行为

- 保持“睡觉 → 提起临时动画 → 松手回到睡觉”，手机、唱歌、待机同理；回到睡觉时继续闭眼，不强制先睁眼。
- 音乐播放与用户选择的模式不被提起动作更改；正在唱歌时仅暂时展示提起姿势。
- 在边界吸附、拉出、快速再次提起、窗口隐藏、切换角色、失去鼠标捕获等路径中清理临时参数。边界吸附可继续用现有探头表现，但不能留下紧张表情或挥臂。
- 静态角色包保持现有提起动作；本期先完成当前 Live2D 模型，不强制要求其他角色新增素材。

## 实施顺序与验收

先做 Cubism 三个臂位和闭眼表情的小样，确认视觉方向，再导出循环和释放动作，最后接入运行层。

- 小样必须清楚看出害怕闭眼、双臂上下扑腾；肩膀连接稳定，袖口不穿模，手臂不双影，画面边界不裁手。
- 鼠标停住时仍继续扑腾；速度不同、帧率不同不改变动作周期。
- 按住移动时抓取点不漂移；松手中断任何一个臂位都能自然收回；快速重复拖动不跳帧或叠加状态。
- 睡觉／手机／唱歌／待机分别验证保存状态恢复，音乐不中断；摸摸、唱歌、转身和眨眼原有表现不退化。
- 单测覆盖动作起始、循环接缝、任意时刻释放、参数归零及原状态恢复；同时检查参数端点及组合下的模型变形。
- 最终用真实鼠标在桌面检查拖动、停住、松手、边界吸附，以及 100%／125%／150% 缩放和多屏；保存录屏或连续截图。模型预览和模拟输入不能代替实际桌面验收。

完整验收定义：视觉小样通过、导出可加载、真实交互验证通过。下面实施记录区分已验证项目与待补充项目；源码启用不代表安装包已经更新。
