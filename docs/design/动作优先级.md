# 动作优先级

2026-10-29。动作的来源与名称分开记录；同样是散步，手动指令和自动触发有不同优先级。

| 等级 | 来源 | 处理规则 |
| --- | --- | --- |
| 100 | 拖起、落地反馈；摸摸由直接互动入口独占 | 优先展示；其他动作不能抢占。拖动时改变保存状态，落地后按最新选择恢复。 |
| 80 | 手动、陪伴对话明确指令，投喂和用户互动 | 可以打断自动动作；工作表现暂让位。正在进行的手动临时动作，聊天页提示等待或停止。 |
| 60 | 工作任务、工作动作预览 | 可打断自动散步、瞬移和自动小动作；不能覆盖睡觉、手机、唱歌、听歌、吸附或用户互动。 |
| 20 | 自动散步、随机瞬移、主动陪伴小动作 | 仅空闲且允许时发生；被更高等级打断后丢弃，不排队补播。 |
| 0 | 普通待机 | 没有更高等级动作时展示。 |

陪伴模式的 API 动作请求在本轮回复完整返回、状态校验通过后按手动指令执行。显式指挥的瞬移使用用户优先级，独立于自动冷却；拖起、摸头、落地反馈仍优先。“停止动作”可结束非鼠标临时动作和预览，但不会停止真实 Harness 工作任务。后台主动聊天不使用这项指令权限。

保存状态仍由 `PetBehavior.mode` 管理。工作姿势是临时显示层，不能把用户原来的状态写成“工作”；完成、失败、取消后恢复当前保存状态。用户改了状态，以新选择为准。

明确的聊天散步走手动入口，忽略随机冷却且不重置截止时间。自动散步的至少 10 分钟冷却保持生效。手动散步期间启动工作任务，只继续后台任务，等待手动散步结束再显示工作姿势。

工作模型眨眼、呼吸使用独立时钟：等待审批时暂停打字和摆腿，但不冻结整个人物。手指、手腕和腿部由模型网格驱动；模型可选，缺少素材时保留正常模型。

实现入口：`deskpet/pet/behavior.py`、`deskpet/animation/work_visual.py`、`deskpet/chat/actions.py`、`deskpet/animation/walk_runtime.py`、`deskpet/chat/companion_runtime.py`。
