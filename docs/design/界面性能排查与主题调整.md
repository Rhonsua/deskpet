# 界面性能排查与主题调整（2026-11-17）

本轮以可复现的界面工作量为依据，使用离屏窗口、少量假数据和隔离存档；没有对用户歌单、API、语音模型或显卡做吞吐压测。源码修改需重启桌宠生效。

## 已处理的重复工作与等待

| 位置 | 原行为 | 修改 |
| --- | --- | --- |
| 聊天流式回复 | 每个增量都删除并插入整条累积回复 | 正常增量只追加新后缀；模型改写前文时才替换当前回复，保留 UTF-16 位置处理 |
| 聊天表情 | 同一表情重复解码，GIF 更新使整段历史失效 | 每次排版复用相同图片；动图只标记实际图片所在位置 |
| 本地歌单 | 界面线程逐首检查文件是否存在 | 后台检查，先显示歌名；切换歌单后丢弃旧检查结果 |
| 节拍分析取消 | 界面线程最多等待进程退出 1 秒 | 立即反馈取消，后台结束后异步清理，旧结果不影响新分析 |
| Live2D 窗口形状 | 重复显示同一帧仍重新计算透明遮罩 | 同一图像帧复用遮罩；新帧失效，位置与缩放仍重新应用 |
| 纪念册和收藏谱 | 隐藏页面也取全量数据、分页、解析收藏谱 | 首次进入才加载；记录与谱面没有变化时复用；新记录仅新增分页 |
| Mod 隐藏页面 | 定时或事件仍更新不可见内容 | 关闭可见页计时刷新，隐藏主面板不读取摘要 |
| 猜歌/三曲演出选曲 | 关闭窗口等待线程扫描结束 | 窗口立即关闭；线程独立存活至完成，迟到结果不触碰已关闭窗口 |

数据库缓存以连接内临时版本表追踪写入，不改存档格式。触发器使用不回滚的单调序号，避免“读取未提交数据→回滚→新写入”重复版本号导致旧内容残留；外部连接修改也会使缓存失效。

小规模检查中，100 次文本增量由重复删除 19,800、插入 20,200 个 UTF-16 单位，变为只追加 400；同一表情出现 10 次仅解码一次。数值表示文档操作量，不等于整机帧率或耗时提升比例。缓存回归覆盖新增、修改、删除、回滚、外部写入和返回值隔离。

## 视觉处理

深浅主题分别定义文字、背景、卡片、输入框和禁用状态，避免继承系统暗色背景却保留深蓝文字。演出页按歌曲、设置与收藏分组，常用入口紧凑排列；高级参数默认折叠，只给开始演出按钮较强强调。纪念册保留暖色纸页与书签。

修正：人物侧栏不等于背景。现在由窗口最底层统一铺满本机现有的天依插画，页面容器和滚动区域保持透明，文字卡片提供深浅两套底色。宽窗口给右侧人物留出空间，窄窗口与书册页使用完整内容宽度。背景副本约 151 KiB，图片仅在创建窗口读取，窗口大小或构图改变时缓存当前可见区域，不随定时刷新重复解码。顶部「调整背景」可拖动位置和缩放，独立保存于 Mod 存档，不改变聊天或歌单的背景设置。

纪念册进一步改为独立透明无边框书窗：进入时隐藏原养成窗口，没有外层底色、窗口标题栏、成长横幅和外部页面标签；书签、返回、关闭、翻页、页码和导出均依附书本，可拖动书页移动整个窗口。返回恢复陪伴首页及其背景，关闭则收起书窗。离屏截图四条外边的 alpha 均为 0，另验证了返回、关闭和拖动。

实际查看了 [Windows 时钟的深浅色示例](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-windows-themes)、[Spirit City 官方截图](https://store.steampowered.com/app/2113850/Spirit_City_Lofi_Sessions/) 和 [osu!lazer 界面图示](https://osu.ppy.sh/community/forums/topics/2221264)。参考的是操作主次、人物留白和参数分组，没有把这些游戏截图或图标装入程序。洛天依主题素材及来源见 `deskpet/mods/bond/assets/SOURCES.md`。

验证包括实际深浅色 QApplication 调色板、深色父窗口、下拉菜单、禁用控件、窄窗口及 150% 缩放截图；真实宿主检查使用独立临时存档，覆盖主面板入口、阶段提示、纪念册、演出和停用清理。

## 仍保留的成本与边界

- 首次加载模型、导入大量文件、巨量聊天记录首次排版和同步存档仍有成本，本轮没有宣称全部改为异步。
- 每个不同的动画帧仍需生成对应窗口形状，不能把运动中的帧当作静态图复用。
- 选曲扫描遇到文件系统阻塞时可以立即关闭窗口；应用最终退出仍等待线程安全结束，未用强制终止线程冒险清理。
- 实际网络中转、长期使用以及不同设备的冷启动延迟不在本轮离线验证范围。

## 第二轮：首次打开组件与后台加载

用户补充重点是组件第一次启动不要阻塞桌宠。本轮检查启动入口、角色准备、聊天/工作模式、语音与音频子进程、云音乐/网页登录、图片和 Mod 页面调用链，区分后台等待与真正发生在界面线程的工作。

| 首次打开/运行路径 | 已落实的处理 |
| --- | --- |
| 聊天 → 工作模式历史恢复 | 历史仅保留原始数据与轻量占位，选中会话才创建 WorkPanel 和排版；未打开记录保存/搜索/退出不实例化，原始内容不丢 |
| 工作模式每秒自动保存 | 先比较文档 revision 与会话状态；未变时不复制全文或编码 JSON，写入失败仍会重试 |
| 表情面板构建、搜索和分类切换 | 后台 QImage 小图解码，最多 256 张缓存；连续搜索合并，隐藏取消，过期结果不回填 |
| 聊天/音乐/养成背景首次加载 | 后台读取与缩小解码；限制图片尺寸，UI 只接收 QImage 转 QPixmap；改图和关闭后旧结果失效，重开可重新加载 |
| 网易云/酷狗页面打开 | 构造不扫描快照，仅进入可见快照页后台读取；注销/切页/关窗取消，旧私人结果不回填。列表只存整数索引，避免复制所有曲目到 QVariant |
| 取消/重启网易云网页登录 | 去掉界面线程最多 1.3 秒的 waitForFinished，旧进程异步退出和超时终止，过期事件不能污染新登录 |
| Live2D 首次触发不同动作 | 初始化后后台预读取动作文件，主线程通过队列接收；切模型和关闭取消旧任务，不共享可写缓存 |
| 重复角色帧准备 | 同一源图且目标尺寸一致时复用缩放图与遮罩，横向姿态或不同尺寸仍单独生成 |

语音合成/模型加载、音频设备准备、网页播放与 Harness 后端已有独立工作进程；网络和安装工作已有异步路径，本轮未用真实 API、语音大模型或用户歌单做压力测试。不要把子进程内的 wait/sleep 当成 GUI 阻塞，也不要仅用 singleShot 推迟整段重任务后宣称异步。

验证：新增线程身份、后台阻塞时 UI 可交互、代次取消、未打开历史保存、自动保存失败重试等检查。合并离线检查 190 项通过；本机模拟 HTTP 与缩放 7 项补查通过。单次隔离启动样本 import=0.419s、construct=1.807s、first_frame=2.289s，仅代表本机本次离屏样本，不是不同电脑的冷启动保证。原缩放测试替身补齐当前角色接口的 character_pack 字段后通过。

仍未彻底消除：静态角色首次 PNG 校验/解码、Live2D 本体与 OpenGL/FBO 首次初始化、首次选择单个巨量历史会话的排版、手动导入多张表情/保存大背景编码、本地 JSON/SQLite 持久化以及最终退出的子进程清理。动作预读尚未完成时保留同步回退，因此不能保证每种首次动作零停顿。这些成本不能据本轮测试宣称完全消失；后续优先拆分角色准备状态机与长历史分页，避免将 GUI/GL 对象直接丢进线程造成崩溃。
