# 陪伴与工作双模式

记录日期：2026-10-29。用户已授权开始接入，原 DSH 候选方向转入实施。具体完成程度以代码、测试和部署记录为准。

## 陪伴模式

沿用现有洛天依完整人格与角色记忆。参考 QQ 社区“大肥鱼”的短句接话、连续记忆、主动关心与表情互动体验，不接入 QQ，也不复制其他角色的人格。

- 回应先理解用户情绪，再自然接话；适当聊音乐、吃饭和日常小事，不机械重复鼓励、不要求用户回应、不因用户离开而责怪用户。
- 主动聊天有独立开关、冷却和空闲门槛。开关说明会消耗所配置模型 API，默认关闭；用户明确打开后生效。
- 动作只能从程序白名单选择，不运行模型返回的代码。模型回复到达后再次检查当前用户状态，过期或取消的回复不展示、不执行动作。
- 用户拖拽、摸头、喂食、手动动作、播放、休息、打开操作面板或工作任务进行中时，避免自主动作抢占；持续状态和临时表现状态分开。
- 工作模式的文件与命令工具不提供给陪伴模式。

## 工作模式

用户最终选择（2026-10-29）：保留官方 Harness 后端，由桌宠原生前端读取状态并接收操作。取消网页入口，直接接 SDK 的任务、工具、审批与结果事件。官方 Web 前端存在工作区插件加载失败，先前“服务启动成功”未能证明网页可用，不再沿用该验收结论。

集成官方 DeepSeek Harness Python SDK，独立运行环境、独立后台进程和数据目录；不要求用户先安装独立 DSH 桌面端。用户仍需填写可用的模型/API 配置。

- 任务界面包括工作目录、任务输入、运行过程、结果、操作确认、停止。
- 文件读取、编辑和命令执行由 Harness 工具循环实现；不能仅让聊天模型输出“我已完成”。
- 工作会话不套用陪伴模式的难题拒答规则，允许正常推理、编程与检查；天依风格只体现在简短状态提示。
- 选中的目录只是工作位置，不等于系统级访问隔离；采用明确权限策略，不默默使用无限权限配置。
- 使用独立 Harness home，关闭默认会话日志外传；任务上下文仍会发送到用户指定的模型服务。密钥不得出现在命令参数、可见日志或仓库中。
- 暂时关闭界面不等于停止任务；退出桌宠与停止操作必须清理任务子进程。停止不承诺回滚已经写入的文件。
- 不默认开放外部聊天发送、发布或自动上传功能。

## 当前交付与使用（2026-10-29）

### 按项目保留工作区与连续会话（2026-10-30 已实现初版）

用户反馈：希望像 DSH 一样把工作模式绑定到项目，保留该项目的窗口/页面，下次进入直接在原项目窗口继续对话、执行任务，也可切换到其他项目继续。当前单页选择目录和“继续上一工作会话”不足以替代项目工作区。

计划交互与数据：

- 原生工作页提供项目列表与最近项目，绑定规范化后的本地目录；重新进入工作模式默认恢复上次选中的项目页面。
- 每个项目保存项目名称、目录、会话标识、历史对话、任务与工具结果、未发送草稿及最后使用时间。每个项目可在后续扩展多个会话；项目与会话标识不能混用。
- 项目窗口/页签保留各自状态；切换项目不清空其他项目记录。用户可选择已有项目继续，或添加项目并新建会话。
- 恢复时读取官方后端已有会话并核对项目绑定，不通过拼接上一轮结果伪造历史。目录移动或丢失时提供重新定位，不能默默绑定到别的目录。
- 关闭页面不等于取消后台任务；切换期间，工具事件和审批始终路由到所属项目/会话。审批不能在别的项目页上误处理。
- 退出并重启后恢复历史和草稿，未完成任务应显示“已中断/待继续”，不能自动重跑命令或恢复旧的批准决定；再次执行由用户发起。首版可继续限定一个运行任务，多项目并行另行设计。

验收场景：项目 A 运行并产生记录 → 切到 B 使用独立对话 → 返回 A 原记录和会话仍在 → 重启桌宠自动回到上次项目 → 继续该项目任务。确认草稿不串、事件不串、审批不串，过期会话和缺失目录可恢复。

2026-10-30：已提供项目选择器与独立原生页面，按目录归一化去重。每页独立客户端、审批与事件记录；切换保留后台任务，同时只允许一个任务运行。`work-projects.json` 原子保存上次项目、每项目当前会话标识、输出、事件和草稿，启动恢复；异常记录保留且不覆盖。重启不会自动执行任务或恢复批准决定。缺少后端会话记录时明确报错，避免假装接续历史。

目前每项目绑定一个可继续的会话；完整多会话列表、目录重新定位、跨项目同时执行仍待实现。页面只保留有限长度的可见输出，完整模型历史由官方 Harness 会话文件管理。

源码已接入双模式。`deskpet/chat/work_panel.py` 提供原生工作页，`work_client.py` 管理独立进程，`harness_worker.py` 连接官方 SDK。任务实际由官方后端运行，不依赖官方网页插件；界面只展示后端回传的进度，不用聊天文字伪造执行结果。

1. 从源码启动桌宠，打开“和我聊天”。陪伴页可分别开启主动聊天与自主小动作，默认均关闭。主动聊天沿用已保存的聊天 API 和天依人设。
2. 关闭操作窗口后，连续空闲至少 45 秒才可能主动互动；聊天请求至少间隔 5 分钟，小动作至少间隔 90 秒。目前小动作使用已支持的开心表现，不宣称已接入模型自由编排动作。
3. 在“API 设置”中保存 DeepSeek 官方服务与模型配置，工作页选择文件夹、输入任务并开始。任务、进度、工具记录和审批都显示在桌宠窗口。本机已安装 `.harness-venv`，其他源码环境运行 `packaging/setup_harness.ps1` 安装固定版本的 SDK 和匹配依赖。
4. 切换页面保留任务；停止任务或退出桌宠会结束后台及其子进程。已写入文件不会自动回滚。任务运行期间暂停主动陪伴，等待审批时不自动批准。

只读取桌宠内部操作状态判断空闲，不监听其他应用的输入或屏幕。主动消息独立保存为角色记忆，不伪造用户发言；手动操作会使尚未返回的主动回复失效。

目前工作模式使用官方 `deepseek-official` 适配器的 Messages 协议。DeepSeek 官方聊天地址会自动转换为对应工作接口，模型名称沿用配置；第三方 OpenAI 兼容聊天地址暂不直接用于工作模式，会给出明确提示。聊天功能原有的自定义接口支持不变。[DeepSeek 官方 API 说明](https://api-docs.deepseek.com/en/) 区分 OpenAI 与 Anthropic 两种地址；不能只因聊天可用就认定工具调用协议也兼容。

初期验证不使用用户密钥；用户随后明确授权真实 API 测试，结果见下方记录。新功能尚未收入 0.5.0 安装包，已有快捷方式指向安装版时不会自动升级。工作动作已有独立 PSD2Live 试作，未修改当前角色模型。验收需覆盖原生界面与实际 SDK 协议，不能仅检查后台端口启动。

## 对话触发动作（已实现）

陪伴聊天页的固定口令继续在本地整句匹配；2026-10-30 增加 API 动作接口，支持自然说法。程序向 API 提供当前模型支持的动作列表，API 仅可在回复首部返回一个 `[动作:英文名称]`。结束回复后校验白名单、请求状态、角色和当前互动，才调用现有动作方法；流式过程中不执行，取消、切换角色或用户状态变化后丢弃旧动作请求。未知、多重或非首部标签不执行，也不显示为聊天指令。

动作范围：挥手、开心、庆祝、吃东西、睡觉、起床、玩手机、持麦唱歌、收麦听歌、转身、左右散步、上下挪动、烟雾瞬移（随机/向上/向下）、工作动作预览及停止动作。实际可用项目随角色素材过滤。吃东西/庆祝只播放动作，不增减音符、饱食或等级；工作预览不操作实际任务。摸头、拖起、放下、鼠标跟随不加入 API 接口。主动聊天请求不提供动作接口。

动作仍检查拖动、摸头、临时动作和播放状态，失败时以程序结果替换模型的动作承诺。对话中的散步和瞬移允许聊天窗口继续显示；鼠标互动保持更高优先级。此次用户要求覆盖全部非鼠标动作，因此瞬移新增显式对话入口，保留自动瞬移开关及原冷却，对话执行不受自动冷却限制且不重置冷却。每轮只执行一个动作，尚不支持跨多轮自动编排动作序列。

验证：63 项本地回归通过；使用用户此前授权的已配置 API，以独立测试消息实测睡觉、上移、工作预览、吃东西、向上瞬移和纯叙述共 6 条，动作意图全部符合预期。测试不上传用户历史、不实际移动角色、不打印凭据。

### 2026-10-30：陪伴歌单播放、正则点歌与恢复按钮

补充口令：唱一下/唱首/来一首＋歌名按点歌执行，支持“你给我”“能不能”等前缀和“给我听”等后缀；未指定歌名的“唱一下”保留为姿势动作。切到/切回 B站或本地直接使用对应音源。用户报告的“给我播放b站合集”已接入本机搜索，将泛称“合集”匹配到标题中的合集/合辑/歌单/串烧；不再依赖模型文字承诺。用户真实记录中该句此前仅有文字应答，未触发播放器。

- 动作白名单增加 `music_play`、`music_local`、`music_bilibili`、`music_resume`、`music_pause`、`music_next`、`music_previous`、`music_stop`。普通口令在本机执行，自然表达走同一 API 动作通道。
- 播放动作支持可选 JSON 参数，例如 `[动作:music_local {"pattern":"^流光$","playlist":"收藏"}]`。只接受 `pattern` 和 `playlist` 字符串；不接受模型指定文件路径、URL 或代码。用户提供正则时保持表达式，普通歌名由模型转义为正则。歌单名准确匹配，歌名正则在本地文件名（去掉扩展名）与已保存 B站标题内搜索；无标题的 B站项可按 BV 编号匹配。
- 搜索使用 `regex` 库，表达式最多 160 字符、标题匹配范围最多 512 字符、单次匹配最多 20 毫秒、整次匹配预算 80 毫秒。超时返回提示，不执行部分搜索结果。跨歌单重复文件去重；零匹配、无效表达式或失效文件均不切换当前音源。多匹配进入第二次异步 API 请求，从最多 60 个真实候选中选出临时编号；取消、换角色或播放状态/歌单改变时不执行旧选择，中间 JSON 不显示、不存入聊天记录。
- 唯一匹配后调用现有音乐面板/B站播放器入口，保留原队列、循环、歌词与节拍准备行为。明确暂停/继续是幂等指令；B站初次加载时暂停会写入待加载状态，避免窗口初始化后又自动播放。API 回复只报告提交/准备情况，真实加载、登录与播放失败由原播放器反馈。
- 音乐指令使用独立的播放状态快照，不能因普通眨眼或动作结束而失效；用户切换了歌曲、歌单或播放状态时，旧 AI 请求不能覆盖新选择。主动聊天不获得音乐控制权限。
- “恢复平时状态”按钮取消旧陪伴请求、结束临时动作和预览；实际工作任务继续，但本次工作展示可隐藏，下一次任务恢复正常展示。音乐继续，人物回到普通姿势，不因音乐又自动进入唱歌姿势。
- 模型接收歌单名、当前播放信息与本轮点歌请求；需要选择版本时额外接收有限候选的标题、来源、歌单名和临时编号，不上传完整文件路径或播放 URL。已有自定义人设保留，内置默认人设同步更新接口能力描述。
- 已通过 71 项相关本地测试和 5 条真实 API 音乐意图/正则参数检查；真实 WebView2 播放器使用静音本地视频完成陪伴播放、初次加载中暂停/继续、结束自动切歌、复用窗口、最终关闭与听歌计时验证。未使用用户 B站账号做在线播放验证，登录/站点验证由实际页面处理。

| 启动/思考 | 看屏幕、轻微点头 |
| 工具执行 | 小幅敲键盘循环 |
| 等待用户确认 | 停止敲击，抬头等待 |
| 完成 | 短暂开心动作，再回到先前状态 |
| 失败/取消 | 停止循环，给简短事实提示 |

工作表现是可打断的临时层，不修改睡觉等保存状态。用户拖起、摸头等动作优先；工作任务可在后台继续。拖动结束后，仅在任务仍运行、没有新的用户意图时恢复工作表现。优先级仲裁不能靠重复覆盖动作实现。

验收：中间帧肩膀无断层、双手不穿桌、八字辫不串位；状态切换不闪烁；任务停止后无残留循环；用户操作不中断；API/依赖首次加载不阻塞渲染。
