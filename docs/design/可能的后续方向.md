## DSH 编码助手与桌宠联动

记录日期：2026-10-28。

**状态：2026-10-29 用户已授权实施双模式接入。下面保留最初候选评估；现行方案见 [陪伴与工作双模式方案](陪伴与工作双模式方案.md)。**

### 用户意图

希望桌宠能接入类似 Codex、Claude Code 的代理执行能力：理解任务、读取和修改项目文件、运行命令、根据结果继续处理。用户明确表示 DeepSeek Harness（DSH）也可以，当前要求只记录为可能的方向。

这比普通 API 聊天或仅调用音乐、提醒等桌宠功能的范围更广。可以探索“带角色陪伴的编码助手”，但不预先承诺与成熟编码代理相同的能力和稳定性。

### 初步判断

复用 DSH 的执行框架具备可行性，第一版接入预计为中等工作量；这是基于文档和现有桌宠架构的工程判断，不是实测结论或工期承诺。

官方 Python SDK 文档列出 Python 3.10+ 与 Windows x64 支持，安装包含匹配的运行时，正常 SDK 执行无需另装系统 Node.js。现有桌宠使用 Python，已有独立后台进程和 API 聊天，可作为界面与进程整合的基础。[官方 Python SDK 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/python-sdk.md)

DSH 的工具、会话、模型适配和代理循环均采用插件架构，具备扩展桌宠联动的入口；具体采用哪个 SDK 配置及事件接口，需在实施时核对固定版本。[官方架构说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)

### 可探索的产品形态

- 作为可选高级扩展，按需安装和启动，控制基础桌宠安装包体积。
- 桌宠提供任务输入、工作目录选择、执行进度、操作确认、取消和结果查看。
- DSH 在独立后台进程执行任务，避免阻塞动作、音乐或界面。
- 天依通过气泡和动作反馈“正在处理、等待确认、完成、失败”等状态，详细过程放任务面板。
- 日常聊天继续保持陪伴人设；编码任务使用独立会话和执行规则，明确界面上的模式，避免原有“日常聊天不解复杂题”等限制误拦截工作任务。
- 用户提供所需模型和 API 配置；实际支持的模型、接口格式与工具调用表现需逐项验证。

### 待验证问题

1. **接入与分发**：Python SDK、Windows 运行时、现有打包方式的兼容性，以及额外下载大小、启动耗时、内存占用。
2. **任务生命周期**：流式进度、操作确认、取消、异常退出和重启后会话恢复；关闭窗口与停止任务的语义需要明确。
3. **文件与命令权限**：工作目录是执行位置，不自动构成访问隔离。官方 `sdk-minimal` 默认使用宽权限本地执行；不能直接当作桌宠默认权限方案，需要评估合适的权限策略和隔离方式。[SDK 权限说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/python-sdk.md#understand-the-minimal-profile)
4. **数据和凭据**：使用独立的 Harness home 和会话目录；明确 API Key、项目上下文、日志的保存及传输范围。官方文档还说明了默认会话日志上传行为，接入时应核实并显式配置，不默默继承已有 DSH 配置。
5. **执行质量与成本**：先验证小任务能否完成，再评估长任务、上下文压缩、循环失败、调用限额及费用展示。
6. **版本维护**：官方当前标注为开发预览，存在不兼容变更；若立项，应固定经过验证的版本，再设计升级策略。[项目状态](https://github.com/deepseek-ai/deepseek-harness#developer-preview)
7. **许可和分发说明**：核对采用版本的 MIT 许可及第三方依赖声明，保留必要声明。[官方仓库](https://github.com/deepseek-ai/deepseek-harness)

### 如果未来决定推进

先在隔离的小项目中验证“读取项目 → 完成一次小修改 → 运行检查 → 展示结果与改动”，再验证取消和确认流程，最后接桌宠状态反馈。第一阶段以验证可用性为目标，暂不扩展为任意桌面操作或完整 IDE。
