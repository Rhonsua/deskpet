# 轻量文字聊天

本轮新增可选的文字对话功能。聊天界面按需打开，原有音乐、成长、拖拽和模型渲染继续独立运行。没有语音合成、声库、麦克风采集，也不需要单独部署服务端。

## 开始使用

1. 右键桌宠，在首页点击“和我聊天”；也可通过系统托盘“聊天”打开。
2. 在“API 设置”填写接口地址、模型名称、API Key。支持 Chat Completions 兼容接口。
3. 地址可以是 `https://服务商地址/v1`，也可以是完整的 `/chat/completions` 地址。没有路径时补 `/v1/chat/completions`，自定义路径则在其后补 `/chat/completions`。
4. 可选“测试连接”，确认后点击“保存配置”。测试会发送一次真实的简短模型请求，可能产生服务商费用。正常聊天使用已保存的配置。
5. 在“人设与记忆”编辑 Prompt 和希望角色记住的事情，在“聊天”中输入消息。Enter 发送，Shift+Enter 换行。

远程接口要求 HTTPS；本机 `localhost`、IPv4/IPv6 回环地址允许 HTTP，不需要鉴权的本机服务可留空 Key。不跟随 HTTP 重定向，请填写最终接口地址。不是所有厂商的原生接口都兼容；接口须支持 `messages`、`model`、`max_tokens`，流式模式还须支持标准 SSE 的 `data:` 和 `[DONE]`。兼容性不佳时可关闭流式显示。

### DeepSeek 官方 Flash

接口地址填写 `https://api.deepseek.com/chat/completions`，模型名称填写 `deepseek-flash`，Key 使用 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建的 API Key。测试连接后保存配置。第三方提供的 Key 需要搭配该提供方的地址与模型名称。

按 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)，模型默认开启思考。桌宠在检测到官方 `api.deepseek.com` 与 `deepseek-flash` 的组合时，自动发送 `thinking: {type: disabled}`，以免短回复／连接测试的输出额度都用于思考而没有正文；其他接口和模型不添加此专用参数。无需在界面另外填写。该适配通过本地请求参数测试，真实服务需用户有效 Key 验证。

窗口包含聊天、API 设置、人设与记忆三个页面；更多设置内也有聊天配置入口。支持随时停止生成。关闭聊天窗口、切换到另一个角色时，会取消未完成请求并恢复输入；失败、取消和截断的回复不会加入下一轮上下文。完成一轮后才一起保存用户消息和模型回复。

## 人设与记忆

- 人设：可编辑的纯文本 Prompt，最多 8000 字符。仅内置一套完整洛天依人设，包含身份日常、性格内核、音乐美食、说话习惯、情绪相处、桌宠状态与记忆规则、示例对话；没有多风格预设列表。
- 记忆：用户手动管理的文字，最多 6000 字符，例如称呼、喜好、希望记住的约定。删除对应文字并保存即可忘记。没有自动提取私人信息，也没有隐藏的长期记忆。
- 上下文：每次最多发送最近 6 个完整来回、累计 12000 字符的历史，再加人设、手动记忆、本次问题和少量当前状态。较旧历史保留在本地，但不会自动全部上传；这版没有自动摘要或向量检索。
- 角色隔离：内置三种洛天依外观共用一个身份；外部角色按角色文件夹选择值独立保存人设、记忆和历史。重命名角色文件夹会形成新的聊天身份。
- 清空聊天：只删除当前角色历史，不删除人设或手动记忆。界面最近显示 60 条消息；暂未提供更早记录的翻页和导出。

编辑人设和记忆后可点保存，发送、切换角色或关闭窗口也会自动保存。模型的人设表现仍受其能力影响。程序把睡觉、待机、等级、当前时间，以及播放时的歌曲标题提供为背景信息；模型没有读取屏幕、操作文件、控制音乐或执行命令的能力。

升级时保留已有自定义人设；如想使用新版，进入“人设与记忆”点击“套用角色默认人设”，确认编辑框内容后保存即可。套用不改变记忆，可以在编辑框中按 Ctrl+Z 撤销。完整人设由项目独立编写，并非官方人设声明。

默认洛天依人格插件保存在 `pet_chat/personas/luotianyi.json`，`persona.py` 保留同内容的故障回退。仅提供一套人格：以官方的温柔、细致、坚强和音乐热情为基础，加入适量美食同人演绎。人设页显示擅长／不擅长的范围；日常闲聊、简单常识与小游戏可以正常回答，复杂证明、考试代答、写代码和专业方案会被提示自然婉拒。用户只是倾诉学习或工作不顺时应回应情绪，不拒聊。

程序将陪伴范围放在可编辑人设之前，插件附上示例。本地规则会直接回应识别到的积分、证明、代码任务，不将这类请求发送到模型；对模型主动输出的明显公式推导或代码，也会在检测到时停止并换成陪伴回应。历史中的此类解题对话保留在本地，但不会再次作为模型上下文。规则有明确识别范围，并非全语言、全表达的语义保证；普通算数、概念闲聊和工作受挫的倾诉正常发送。

外部角色可以在角色目录添加 `personality.json`。文件只含文字资料，不执行脚本、不增加模型权限，也不能关闭本地陪伴限制；错误文件回退，不影响图片加载。格式、资料来源和验证用例见 [洛天依人格资料与插件](洛天依人格资料与插件.md)，可复制模板见 `characters/example/personality.json.example`。初音未来另有独立的 [Miku 人格模板与资料](初音未来人格资料.md)，不改变默认洛天依的一套人格设计。

## 回复与动作

可以由模型在回复开头给出情绪标签，程序剥离已知标签后显示正文。无标签的文字正常展示。第一版只有“开心／欣喜”映射到已有开心动作，其余语气保持当前动作，等待以后补充对应表情资源。

睡觉、玩手机、拖动、进食等已有临时动作进行时，不被聊天表情打断；普通状态下的开心动作结束后恢复原活动。长回复完整显示在聊天窗口，角色旁气泡最多显示前 160 字符。全部文字转义显示，不解析模型输出的 HTML、链接资源或指令。

## 数据与密钥

数据保存在现有本地应用数据目录的 `chat/` 子目录，与音乐成长数据库分离：

| 文件 | 内容 |
| --- | --- |
| `config.json` | 接口地址、模型、流式开关、加密后的 Key（选择记住时） |
| `chat.db` | 各角色的人设、手动记忆、已完成的聊天 |

“记住 Key”使用当前 Windows 用户的 DPAPI 保护。加密失败时不保存明文，可取消记住后仅在本次进程中使用；重新启动需再填。跨电脑或跨 Windows 用户复制配置后，可能需要重新填写 Key。聊天记录本身保存在本地 SQLite 中，未额外加密。

打开聊天窗口或启动桌宠不会发起模型请求。只有“发送”和“测试连接”访问用户配置的模型服务；服务商的计费和数据处理规则由用户自行选择的服务决定。聊天不会上传歌曲文件、原始素材、完整听歌记录或整个磁盘文件。关闭流式显示不改变发送内容。

## 文件分工

新功能集中到 `pet_chat/`，避免把网络和聊天存档塞进原有渲染、音乐文件。

| 文件 | 职责 |
| --- | --- |
| `pet_chat/config.py` | 地址规范化、配置读写、Windows Key 加解密 |
| `pet_chat/store.py` | 独立 SQLite 存档、角色隔离、完整对话事务 |
| `pet_chat/prompts.py` | 默认人设、有界上下文、情绪标签容错 |
| `pet_chat/persona.py` | 一套完整的洛天依桌宠人设文本 |
| `pet_chat/protocol.py` | 增量 UTF-8/SSE 解析与格式校验 |
| `pet_chat/client.py` | Qt 异步 HTTP、90 秒超时、取消、错误处理 |
| `pet_chat/window.py` | 按需加载的聊天、设置和人设界面 |
| `tests/test_pet_chat.py` | 协议、存储、配置、DPAPI 单元检查 |
| `tests/smoke_chat.py` | 本地模拟 API 与真实 Qt 桌宠集成检查 |

现有 `desktop_pet.py` 仅增加入口、角色切换通知、聊天打开时保持展开和纯文本气泡；`compact_ui.py` 增加配置入口。没有新增第三方运行依赖。使用已有 PySide6 的 QtNetwork，不在界面线程中执行阻塞 HTTP。

页面响应优化：网络模块和连接管理器延迟到首次发送／测试时创建；未改变的人设不反复写数据库；流式回复只增量更新当前消息，不重新读库或排版全部历史。切到 API／人设页面时暂停聊天区流式刷新，返回时补齐；显示区最多保留最近 60 条且累计约 30000 字符，完整历史仍在本地。可用 `tests/benchmark_pages.py` 在临时数据下测量页面首次打开和长历史更新，不调用付费模型。

同机离屏测量：包含长历史的 30 次流式更新由约 520 毫秒降至约 17 毫秒；优化后聊天首次打开约 61 毫秒、重新打开约 2 毫秒，API／聊天页切换约 2 毫秒，完整人设页首次排版约 16 毫秒。这个测试使用静态角色和临时存档，并不等同于真实桌面上 Live2D、多显示器或慢磁盘场景的帧率保证。

## 参考与验证范围

参考 [Agent-LuoTianyi](https://github.com/SheepLiu712/Agent-LuoTianyi/tree/3368f3e574845d04c4069795a317aadfec722e0d) 的用户自带模型配置、人设／风格／记忆组合、情绪标签与表情映射思路。本实现独立编写；没有复制其源码、人设原文、模型、知识库或语音资源，没有接入其远程服务端。这里采用单个模型请求、手动记忆及现有动作，未引入它的 Agent 调度和数据库检索体系。

验证命令：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_pet_chat.py -v
.\.venv\Scripts\python.exe tests/smoke_chat.py
```

集成测试仅访问临时本机模拟接口，使用临时配置与数据库，无真实 Key，不产生模型费用。真实服务商连接与模型回答质量需要填写有效配置后验证。这轮为源码更新，既有安装包不会自动获得此功能。

2026-10-21 本地验证：全部 107 项逻辑测试中 106 项通过，1 项因系统无法创建符号链接而跳过；新增 10 项聊天逻辑检查全部通过。聊天集成检查覆盖流式／非流式、鉴权错误、禁止重定向、截断回复、取消后迟到响应、角色切换隔离、休息状态保持、开心动作、文字转义、清空历史与重新打开；原有桌宠界面检查通过。已查看聊天和设置的实际 Qt 截图，中文和输入框对比正常。本机 Qt TLS 后端可用，未使用真实 Key 请求远程模型。
