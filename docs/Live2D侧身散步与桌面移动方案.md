# Live2D 侧身散步与桌面移动方案

日期：2026-10-24。状态：仅设计，尚未制作侧身原画、Cubism 绑定或桌面移动逻辑。

## 目标与制作基线

天依在空闲时随机触发一次短暂的左右散步：随机选择向左或向右，先转向行走方向，再交替迈步，在桌面上缓慢移动；到边缘停下、转身，达到本次行程终点后结束。自动触发后至少冷却 10 分钟；手动触发不受这个冷却限制。散步是可被用户随时打断的临时状态，结束后回到保存状态。用户提起时立即进入现有 `> <` 闭眼挥臂，放下后恢复用户保存的状态，不继续被打断的路线。

以 `experiments/live2d-tianyi/lift-model/tianyi-lift.cmo3` 为制作基线，开始时另存到独立 `walk-model/`。当前桌宠入口是 `assets/live2d/tianyi/action-map.json` 指向的 `tianyi-lift.model3.json`。已有横转是小幅二维透视变形，双腿没有完整膝踝结构，不能把当前转脸幅度加大就称为侧身行走。

首版建议左右各一套三分之二至四分之三侧向的步行姿态，脸仍能看到，后续再考虑完整 90° 侧面。先验收左右侧向静帧，再制作动画，避免在错误衣服、发型或肩部上继续绑定。

## 素材与 Cubism 分件

- 保留公式服、八字辫和原有身材比例。左右服装不对称，黑色长袜的位置必须保持；不能用整个人物水平翻转代替左右转身。
- 补齐侧脸、后脑与辫根、远侧肩臂、裙摆内侧、髋部遮挡、膝后及鞋底。走路需要露出的区域必须有真实原画，不能拉伸空白或旧袖口补洞。
- 左右腿按大腿、小腿、鞋拆分；手臂按上臂、前臂和手分层。关节处保留重叠余量，皮肤、袖子、裙摆分别处理遮挡。
- 设置步行专用部件组，与现有站立、睡觉、手机姿态互斥。过渡期间避免半透明叠出两张脸、四条腿。近远侧绘制顺序在转身时明确切换。
- 现有提起肩部变形、唱歌持麦和摸头绑定保留；步行的参数与变形器单独命名，默认值不改变现有动作。

建议参数合同（名称待制作时最终确认）：

| 参数 | 范围 / 默认 | 用途 |
| --- | --- | --- |
| ParamWalkFacing | -1～1 / 0 | 左侧向、正面、右侧向；只是姿态值，不是物理角度 |
| ParamWalkWeight | -1～1 / 0 | 左右支撑重心 |
| ParamWalkHipL / R | -1～1 / 0 | 独立大腿前后摆动 |
| ParamWalkKneeL / R | 0～1 / 0 | 摆动腿屈膝 |
| ParamWalkFootL / R | -1～1 / 0 | 脚掌接地、抬脚与脚尖落地 |
| ParamWalkArmL / R | -1～1 / 0 | 与腿反相摆臂 |
| ParamWalkBounce | 0～1 / 0 | 小幅重心起伏 |

步行相位由运行层计算并采样动作，不必再让 Cubism 的多个参数各自充当计时器。侧向与腿、手臂、呼吸的关键值组合必须逐项检查；支点位于真实关节，避免整个袖子像贴纸一样转动。

## 步行循环与转身

先制作约 1.2～1.6 秒的双步循环，以最终观感调节，不作为硬性速度要求：左脚接地 → 重心越过左脚 → 右脚抬起经过 → 右脚接地 → 对称另一半循环。支撑脚应在桌面坐标中近似固定，摆动脚才前移。

手臂与对侧腿同步，头部轻微稳定，发尾与裙摆稍滞后；幅度克制，先保证鞋底和关节连续。完整循环首尾形态与速度需连续。做独立的起步、停止、左转和右转过渡，不在行走中瞬间镜像。

模型只负责局部姿势与小幅起伏，窗口负责水平位移。标定一个完整循环实际跨过的距离，运行速度按“每秒循环数 × 每循环步幅 × 显示缩放”计算。窗口移动速度和步频一起变化，不能一个固定另一个随机，避免滑步。

## 随机触发与冷却规则

- 自动散步启用时，由桌宠在空闲待机、可见、未吸附且没有用户交互或其他临时动作时随机触发；睡觉、玩手机、唱歌、拖动、摸摸或打开工具窗口期间不触发。
- 每次在可行方向中随机选择左或右；一侧空间不足时选另一侧，两侧都不足则跳过。本次散步有有限的距离或时长，完成后停止，不无限来回巡逻。具体距离与时长在动画验收时调节。
- **自动触发成功时开始至少 600 秒的冷却**，冷却内不能再自动散步；提前结束或被用户打断也不能清空冷却。触发检查未通过不算成功触发。
- 冷却到期只表示重新具备触发资格，不要求满 10 分钟立即行走。建议在 600 秒基础上增加随机等待，使触发时间自然；不逐帧抽签，也不补执行休眠或忙碌期间错过的散步。
- 手动“散步”可绕过自动冷却，但仍遵守姿态、边界和用户交互条件；手动触发不消耗、重置或缩短已有自动冷却。手动散步期间不会叠加自动散步。
- 运行中用单调时钟计时，并保留自动冷却截止记录，重启或切换角色不应让尚未结束的冷却提前失效。临时行走状态和路线不持久化，重启不会续走。

## 桌面移动与状态归属

新增独立移动控制器（拟名 `walk_controller.py`），使用单调时钟和实际时间差，不按帧数移动。记录小数位置，提交窗口位置时再取整，防止低速抖动；电脑休眠恢复或卡顿时限制时间差，避免跳到屏幕另一端。

`PetBehavior.mode` 仍保存用户选定的待机、睡觉、手机、唱歌、听歌状态。散步属于可中断的临时过程状态，不能写入保存状态，也不能覆盖音乐播放意图。用户操作优先于散步，不需要等待一轮步行动画播完。建议处理顺序：

| 情况 | 行为 |
| --- | --- |
| 用户点击“散步” | 从待机起步，绕过自动冷却；当前睡觉、手机等姿态先说明需切回待机，不能偷偷唤醒 |
| 自动散步 | 空闲且符合条件时随机向左或向右走，成功触发后至少冷却 10 分钟 |
| 点击、按住或右键桌宠 | 立即停止自动位移并取消本次路线，再按原交互规则响应，不吞掉用户操作 |
| 鼠标提起 | 立即停止窗口自动移动，进入现有提起动作；落地后回保存状态，取消这次行走路线 |
| 摸摸、投喂、打开控制面板等工具窗口 | 取消散步并让用户交互；不与挥臂、摸头争抢参数 |
| 用户切换睡觉、手机、唱歌 | 取消当前散步并进入新状态；不影响音乐播放本身 |
| 切角色、隐藏、退出、失去鼠标捕获 | 清理移动计时与临时参数，不留下后台移动 |
| 自然结束或点击“停下” | 停止位移，双脚落稳后回保存状态；用户打断时立即响应，不等待收尾动画 |

中断只清理散步的临时动作、速度与路线，不清空已经开始的自动冷却。若用户同时选择了新模式，以新选择为准；其他交互结束后恢复原保存状态，不自动续走。

首版不做边走边持麦唱歌，避免现有唱歌腿部曲线与步行互相覆盖。渲染层明确选择唯一的主动作，鼠标跟随在走路时限为小幅眼神，不能把头身体转回另一方向。

使用当前屏幕的可用区域（扣除任务栏），以角色可见脚底作为水平地面锚点，转身和改大小后仍保持脚底位置。首版在当前显示器内移动；屏幕有负坐标、不同缩放或拔掉显示器时，重新计算可用边界并收回角色。坐标统一使用 Qt 逻辑像素。

自动走到边缘应减速停步、转身，不触发用户拖动的探头吸附。已吸附时不自动起步。现有用户拖动吸附规则保持独立。歌词继续跟随人物位置，仍允许到屏幕边界。

入口建议放控制面板：“散步 / 停下”和“随机散步”开关；开关用于控制自动触发，手动入口独立。托盘保留停止入口，保证鼠标穿透时也能关闭。不新增强制打断用户的弹窗。

## 接入文件与兼容性

- Cubism 工程及素材：新增 `experiments/live2d-tianyi/walk-model/`，保留当前提起版本作为回退。
- `live2d_motion.py`：添加步行动作组和参数复位，明确与唱歌脚步、指针跟随的优先级。
- `desktop_pet.py`：驱动移动控制器，处理窗口位置、拖动、中断和屏幕变化。
- `pet_behavior.py`：接入可中断的临时行走状态，保留原 `mode` 与现有提起恢复语义；移动控制器区分手动与自动来源，负责随机调度和至少 600 秒的自动冷却。
- `action-map.json`：登记可选的步行能力、左右动作和脚底锚点。缺少能力或参数的角色正常待机，界面不提供无效散步操作。
- 当前动作读取器只接受线性与阶梯分段；Cubism 导出的贝塞尔曲线需要先采样烘焙成支持的分段，或单独完善并验证读取器，不能直接交付无法播放的动作。
- 每次 Editor 导出后恢复 `.model3.json` 的动作引用；校验全部文件、纹理和参数，再更新正式入口。

## 实施顺序与验收

1. 左右侧向静帧：检查公式服不对称、八字辫位置、肩袖衔接、脚底基准；通过后才拆件。
2. Cubism 原地循环：先腿和重心，再手臂、发裙、表情；检查端点、中间值、呼吸组合与近远侧遮挡。
3. Viewer 中连续观察至少三个循环，以及起步、停止、左右转身。保存可回看的预览与实际观察记录。
4. 接桌面平移：先固定单方向，再边界转身，最后加入随机左右散步、自动冷却和交互中断。
5. 自动检查时间差、步幅同步、左右边界、负坐标、状态恢复、重复启停、缺少步行能力回退。用可控时钟验证自动触发后 600 秒内不再触发、打断不清冷却、手动绕过且不改自动冷却、到期仍需符合触发条件、重启不提前解锁。验证点击、拖动、右键和切换模式均能取消路线且不吞操作。真实桌面另验收不同缩放、多屏、任务栏、静止长按提起与落地；不能拿模拟输入替代目视验收。
6. 回归待机、唱歌、睡觉、手机、摸头和本次提起动作，确认无新增残影、衣料缺口和默认姿态变化，再部署。安装包另行按用户要求制作。
