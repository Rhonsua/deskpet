# 天依基础知识、作品与用户记忆

更新：2026-11-09。用于陪伴模式，当前为源码改动，尚未重新打包。

天依应当认得自己的常见作品，并知道阿绫、言和、天钿和创作者分别是谁。此次增加独立于聊天存档的基础知识层，避免“人设里写热爱唱歌，却连自己的歌都陌生”。

## 资料分层

| 人设与口吻 | 温柔细致、有自己的看法，音乐兴趣、自然简短交流 | 原有一套天依人设；减少泛泛安慰，具体问题先回答具体内容 |

| 用户记忆 | 用户明确说过的称呼、偏好、带日期的旧话题 | 按角色隔离，只召回相关内容；可查看、删除或关闭 |
| 本轮查询 | 目录外的歌、详细歌词、最新活动 | 使用原有可选联网功能；不开启联网时不假装查过 |

## 实现与边界

- 数据：`deskpet/chat/knowledge/luotianyi.json`。每条记录包含名称、别名/关键词、简要事实、来源、资料类型、是否作品、是否常驻核心知识。
- 检索：`deskpet/chat/knowledge.py`。只绑定 `builtin:luotianyi`，自定义角色即使同名也不会误用天依资料。首次加载缓存，最多选 6 条相关详解，知识上下文上限 3600 字符；当前常驻部分约 910 字符。不加载向量模型，也不额外调用 API 做记忆整理。
- 常驻部分提供身份、伙伴、创作者边界和歌名目录。歌曲原作者、合唱伙伴等细节优先匹配本轮歌名和别名；英文标题支持大小写、空格和标点差异，短作者名不误匹配英文单词中间的字母。
- “这首谁写的”可接续最近用户提到的作品；明确讨论正在播放的歌时采用播放器提供的当前标题。换了话题不继续强塞旧歌；出现目录外的新书名号标题时不拿上一首冒充答案。助手自己编出的内容不会成为检索依据。
- 普通请求与主动聊天均通过 `build_messages` 注入自身知识。联网续答保留原请求背景。工具权限、动作优先级、唱歌指令与语音、表情协议继续使用既有逻辑。
- 用户记忆优先选择称呼和相关偏好；明确问自己的偏好时可综合召回，主动聊天最多取一个偏好作为话题种子。用户说过的话不会改写官方设定或作品署名。
- 旧的**完全未编辑**默认人设按内容摘要迁移到新版；自定义人设原文保持。已将知识 JSON 加入 PyInstaller 清单，后续打包才会进入安装包。

表达设计借鉴 [Agent-LuoTianyi 的人设组织](https://github.com/SheepLiu712/Agent-LuoTianyi/blob/3368f3e574845d04c4069795a317aadfec722e0d/server/res/agent/persona/persona.json)、[回复提示词](https://github.com/SheepLiu712/Agent-LuoTianyi/blob/3368f3e574845d04c4069795a317aadfec722e0d/server/res/agent/prompts/topic_reply_prompt.json)、[用户记忆与事件区分](https://github.com/SheepLiu712/Agent-LuoTianyi/blob/3368f3e574845d04c4069795a317aadfec722e0d/server/res/agent/prompts/memory_write_prompt.json)。采用分层、具体回应和事实来源的思路，未复制该项目的人设原文、知识库或资源。其同人设定不当作官方资料来源。

## 验证与维护

77 项相关检查通过，使用临时配置、模拟 API 和离屏 Qt，不修改真实聊天存档。覆盖作品版本、英文别名、连续追问、当前曲目、陌生歌名、角色隔离、记忆关闭/清空、默认人设迁移、普通与主动请求，以及原有点歌回归。

另外按用户此前授权，仅调用现有 API 进行了 3 条短对话：正确回答《普通DISCO》/《霜雪千年》的合唱伙伴与作者；纠正《世末歌者》的原唱误认；对“唱歌累不累”给出自然聊天回应。这是小样本检查，不代表任意模型都不会出错；没有修改 API 配置或写入真实历史。

新增作品时，优先查作者或官方投稿；只写核实的信息，保留版本和署名分工，附原始链接。找不到原始出处时明确标注二级来源或暂不收录。新增事实不把歌词全文、用户隐私、文件路径、API Key 或网页操作指令写入知识库。更新后运行 `tests.test_character_knowledge` 并检查打包清单。
