# B站合集与收藏夹导入

## 怎么用

入口：打开歌单 → B站 → **导入合集 / UP 主 / 我的收藏夹**。

- **自己的收藏夹**：点击“我的收藏夹”，直接读取桌宠 B站播放网页的当前账号。选择列表，点“一键添加选中列表”。还没有登录时会打开官方登录网页，成功后自动读取；也可以再点“我的收藏夹”重新检测。
- **某位 UP 主的合集**：粘贴 UP 主主页或 UID，点“读取并添加”，随后选择合集或系列。也可以直接粘贴具体合集链接。
- **收藏夹分享链接**：粘贴 `https://www.bilibili.com/list/ml编号` 或旧版空间收藏夹链接，点“读取并添加”，整份加入当前 B站歌单。
- **多 P 视频**：在导入窗口粘贴视频链接，全部分 P 分别加入；若视频属于 UP 主合集，则导入该合集。只想加一个分 P 时，仍使用 B站主页面原来的“添加链接”入口。
- **手机分享**：支持从分享文字提取一个 B站链接；`b23.tv` 短链接会在后台展开。

导入只保存播放链接和标题，播放仍使用 B站官方网页，不下载 MP3 或视频。添加后可按歌曲标题在陪伴模式点歌。

## 登录与保存

复用 `%LOCALAPPDATA%\TianyiPet\WebPlayer` 的 WebView2 登录状态，与桌宠播放 B站时使用的是同一个账号。不会读取系统 Edge、Chrome 的浏览器资料；在外部浏览器登录不等于已在桌宠登录。

账号状态通过原有网页进程读取，登录凭据只通过 Windows 加密后的进程消息临时传给导入任务；不再复制到另一套账号配置，不打印凭据或写入歌单。每次读取都重新接回当前网页登录状态，以支持网页端退出或切换账号。

如果正在播放，登录使用同一浏览器环境的独立窗口，避免把播放页切走。未登录或会话过期时，不会把空结果写回原有歌单。

## 导入行为

- 逐页读取完成后，一次性追加到已有歌单，不覆盖原内容；按规范化的视频 URL 去重，保留不同分 P。
- 同步视频标题，保留正在播放的歌曲、位置和播放状态。结果使用原来的歌单保存机制，重启后保留。
- 可取消；取消或窗口关闭后，迟到的结果不再写入。读取中途失败不会保存半份列表。
- 跳过可识别的失效视频与非视频项目；站点后续删除或限制的视频仍可能在播放时提示不可用。
- 单次最多 5,000 个视频、200 页、180 秒，超限会提示选择较小的合集，不静默截断。
- UP 主“全部视频投稿”使用签名接口，可能受 B站验证或频率限制；失败时建议登录后重试，或直接选择具体合集。读取不会绕过收藏夹权限。

## 实现与验证

播放恢复会等待页面加载、缓冲与跳转完成，避免把播放状态迟报误判为失败、反复重播开头。开始播放后如网站突然恢复旧历史进度，会接回本次连续播放的位置；不会为了恢复再次从零播放整段开头。手动暂停、拖动进度优先于自动恢复。真正未能跳转到开头时才有限重试；已经听到开头后不再用刷新页面的方式重新播放。

2026-11-11 补充修复：每次起播/恢复指令带独立编号，同一指令因网页回执丢失而重试时不重复归零；网页记录实际到达开头的位置与时间，不再单靠 `seeked` 回执判断起播成败。进度跳变判断同时参考网页采样时钟，容忍小幅进度追赶，保护期结束后不继续纠正进度。主动重播、单曲循环和选择下一首仍会使用新指令，从头开始。

2026-11-12 真实网页前 3 秒复测：发现页面可能在桌宠首次探测前已自动开播，第一条起播指令仍会把它拉回零。现于页面初始化时记录原生起播；只有确认同一视频从开头连续播放、期间没有跳转时，才保留现有进度。明确重播、单曲循环和旧历史位置仍正常归零。高频实测修复前 6 轮发现 3 次回退（其中 2 次在前 3 秒）；修复后同样 6 轮，前 3 秒 153 点、延长观察共 570 点，未发现回退。测试为强制静音、独立未登录 WebView2 配置；有限样本不代表全部网络条件。

可用 `tests/live_bilibili_stats.py --live-network --focus-opening` 复测真实网页。每 100 毫秒定时采样并监听媒体事件，记录覆盖首次桌宠探测之前的自动播放；具体点数取决于页面负载。报告写入本机 `local-work/reports/`，临时浏览器配置用后清理；不会运行于普通单元测试。

回归检查：`tests/test_web_playback_guard.py` 覆盖迟报、回执缺失、媒体替换和历史跳转；`node tests/test_bilibili_probe.cjs` 验证真实探针脚本的重复指令处理。`tests/smoke_web_loops.py --lost-reply --slow-start --background` 使用临时 WebView2 与静音视频，模拟已经播放 3 秒多才重试指令，验证进度不倒退及循环/切歌正常；不使用真实登录资料。

- `bilibili_import.py`：链接识别、短链展开、合集/系列/收藏夹分页、UP 主目录、WBI 投稿请求。
- `bilibili_import_dialog.py`：后台任务、取消、目录选择、追加结果和登录状态请求。
- `bilibili_account.py`：在既有 WebPlayer 中读取站点 Cookie；按用户请求打开共享登录窗口。
- `bilibili_player.py` / `web_player_worker.py`：沿用现有进程协议和播放队列，增加带请求编号的账号读取消息。
- 测试：`tests/test_bilibili_import.py`，搭配原有 B站链接与本地/B站轮流播放测试。

接口与链接形态参考 [yt-dlp 的 B站提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py)。没有增加 yt-dlp 运行依赖，导入过程不提取媒体下载地址。
