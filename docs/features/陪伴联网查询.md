# 陪伴模式联网查询

陪伴页新增 **联网查询（歌曲、歌词与资料）** 开关，首次默认开启，用户关闭后记住选择。无需另填搜索 Key；聊天继续使用原来的接口、模型和 Key。

## 使用

- “查一下《普通DISCO》的歌词，聊聊它想表达什么。”
- “结合现在播放的这首歌，解释一下我刚才引用的那句话。”
- “查查天钿的设定。”

模型根据整句话决定是否查询。普通闲聊、歌曲播放、动作指令不因为出现关键词而强行查询。主动闲聊不会自行联网。

讨论当前歌曲时优先使用**发送问题那一刻**已绑定的 LRC/SRT；不改播放状态、歌词绑定和文件。缺少歌词时匿名查询公开音乐资料，其他资料使用公开网页搜索。当前实现先尝试已有酷狗歌曲/歌词接口；网页使用 360 搜索，失败时尝试 Bing RSS、DuckDuckGo。网页结构、网站验证和网络情况会影响可用性，查询失败会明确提示，不把无关结果当作查到了。

结果回传后，天依再结合原问题解释或接话，歌词以意境分析和自己的话为主，避免复制整段歌词。回复附可点击的**查询来源**；来源链接不参与语音朗读，重开聊天仍保留。搜索摘要与实际网页正文在内部资料中区分，不把摘要说成全文。

## 调用与数据

每轮最多一次查询、一次查询后的回复：通常共两次聊天 API 请求。查询阶段只向公开站点发送必要的搜索关键词，不发送 Key、登录 Cookie、个人记忆或整段聊天。查询资料会交给用户配置的聊天模型生成回答。

使用独立后台任务，限制响应大小和查询时间；“停止”、关闭联网开关、换角色或进入工作模式会取消未完成流程，旧结果不能写入新会话。页面中的文字只能作为参考数据，不能驱动桌宠动作、命令执行或追加搜图。

协议为单条 `[联网:{"kind":"lyrics","query":"歌名 歌手","current":true}]`，或 `kind=web`。界面不显示也不朗读协议标签。查询完成后不允许再查询，只有实际返回的来源才显示在消息旁。

## 语音与普通互动

拖动、点击、摸头等普通互动不取消已经开始准备或播放的语音。尚未生成语音的空闲主动聊天仍会让出时机，避免打扰用户。明确“停读”、发送新消息、切换角色/工作模式或退出仍可停止语音。

## 验证

- 自动检查覆盖：协议、取消与迟到结果、来源持久化、语音分离、当前歌曲切换、外部资料不能触发动作。
- `tests/smoke_lookup.py --live-network` 显式运行公开网络检查；加 `--config` 可按需运行两次真实模型请求，不上传用户原有聊天历史。
- 已以《普通DISCO》实测“模型请求 → 公开歌词 → 模型解释 → 来源显示”的完整流程；普通网页资料也进行了实际查询。
