# GitHub 发行与桌宠更新

0.6.2 已加入更新检测，入口在「打开歌单 → 设置 → 版本与更新」。此前生成的 **0.6.1 安装包不包含此功能**，用户需要先手动安装一次 0.6.2 或更高版本。仅在 GitHub 上传安装包不会改变已经安装的旧客户端。

## 用户操作

- 默认后台检查，启动约 30 秒后首次尝试，此后两次自动请求至少间隔 12 小时。可关闭后台检查，或随时点击「检查更新」。
- 有新版时显示版本号、安装包大小与发行公告，可选「下载更新」「稍后再说」「跳过此版本」。手动检查仍能看到已跳过的版本。
- 下载在后台进行，可以取消。联网失败不影响桌宠、播放和工作任务，也不会自动替换当前程序。
- 下载完成并核对文件大小与 SHA-256 后，再由用户选择「退出并打开安装程序」。这会停止当前播放和工作任务，请先处理正在进行的任务。
- 安装器默认使用上次安装的位置，点击安装后更新。听歌记录、歌单、聊天、背景、独立角色、Mod 和 Harness 后端位于用户数据目录，不在更新时清除。安装器保留程序目录内额外放入的文件。
- 源码或免安装运行时，更新提示打开 GitHub 发行页，用户自行下载安装并选择位置。

## 维护者发布步骤

以之后的 `0.6.2` 为例，版本号应与实际构建一致：

1. 修改 `deskpet/version.py`，准备对应版本的更新公告，并用 `packaging/build_installer.py` 生成安装包。
2. 打开 [Rhonsua/deskpet 的发行页](https://github.com/Rhonsua/deskpet/releases)，选择创建新发行版。
3. 标签填写 `v0.6.2`，名称可填写「天依桌宠 0.6.2」，正文填写本次更新内容。
4. 附件上传 **`TianyiPet-0.6.2-Setup.exe`** 和构建时生成的 **`dist/SHA256SUMS.txt`**。不要改安装包文件名。
5. 发布为正式发行版，并将它设为 Latest。草稿和勾选 Pre-release 的预发行版不会推给普通用户。

安装包作为 Release 附件上传，不放进 Git 提交历史。GitHub 自动附带的「Source code」压缩包只是源码，不能代替 Windows 安装包。

客户端只读取本项目公开仓库的最新正式发行版，按数字比较版本，例如 `0.6.10` 大于 `0.6.9`。不会降级，不需要用户填写 GitHub Token，也不会把聊天 API Key 发给 GitHub。

优先采用 GitHub 提供的安装包 `digest`；没有时读取同一发行版的 `SHA256SUMS.txt`。两者都没有则不在应用内下载安装，提示前往发行页。未完成或校验失败的文件不作为安装包使用。下载缓存放在桌宠用户数据目录的 `updates/<版本号>` 中。

GitHub 无法连接时，可以继续使用原版本；用户也可从发行页手动下载。此功能不包含镜像源、静默强制更新或增量补丁。

接口依据：[GitHub 最新正式发行版 API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)、[GitHub 发行附件 API](https://docs.github.com/en/rest/releases/assets)。
