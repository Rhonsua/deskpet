# 工作模式自动审批

2026-10-30 实现。工作页增加“总是允许普通操作（高风险仍需确认）”，默认关闭，按项目保存在 `work-projects.json`。首次开启以及关闭后再次开启均需确认提醒；重启恢复已确认的设置时展示持续说明，不自动开始工作。

## 权限与提醒

复用当前固定版本官方 Harness 的 `@deepseek-ai/dsh-experimental-auto-review`，不使用正则黑名单猜测任意命令是否安全，也不在前端把所有审批直接回复为允许。

- 开启：官方 Auto 在工具执行前进行模型审查，低风险及已获授权的普通操作可以执行，高风险和未获授权的操作转到现有手动审批界面。每次允许仍只针对当前操作。
- 审查失败或响应不合规范：工具不执行，保留错误反馈，不默认放行。
- 官方 Auto 的执行范围是完整主机访问，没有项目文件夹隔离。模型审查不是绝对安全保证；开启提示和页面说明均注明这一点。
- 每次审查会使用已配置 API 和任务上下文、工具参数，增加调用费用与耗时，开启时明确提醒。
- 任务开始后锁定开关；不会改变正在执行的工具权限。停止或结束后可关闭，下一轮含恢复旧会话按新设置执行。

## 接入方式

`work_permissions.py` 生成运行配置，保留 `approval: ask`；普通模式以 `workspace-write` 启动。自动审查模块在关闭时仍挂载，以便安全恢复之前选择 Auto 的会话。

`harness_permission_bridge.mjs` 在当前根会话每个步骤开始之前应用桌宠设置：开启选择官方 `auto`，关闭选择 `workspace-write`。官方服务未注册时选择会失败，不降级成无审批完全访问。子代理沿用官方权限继承规则。

前端继续接收官方审批请求，关联同一会话与工具调用的完整参数，并等待用户明确允许或拒绝。没有新增全局“永远允许全部命令”回复。

## 验证

30 项相关单元测试通过，覆盖开启提醒取消/确认、权限参数、项目独立记忆、会话与审批队列等。`tests/harness_auto_approval_smoke.py` 使用真实官方运行时与本机模拟模型验证：

1. 普通命令经自动审查后执行，没有人工审批请求。
2. 模拟高风险审查产生人工审批，拒绝后临时标记文件未创建。
3. 错误审查响应不会执行命令。
4. 同一会话关闭 Auto 后恢复普通审批，且不再发出自动审查模型请求。

集成测试仅操作临时目录并使用模拟审查结论，验证执行门控；不代表真实模型对任意命令的风险判断准确率。
