# 陪伴自主选歌

当用户把选歌交给天依时，她可以从真实歌单选歌并提交播放，不再仅回答“这就挑一首”。

## 使用

- “随便唱首歌听听”“随机放一首”“你挑一首吧”“放歌啊”：直接随机挑选并播放，不需要额外调用聊天 API。
- “选一首适合放松的歌”“帮我挑一首睡前听的歌”：把真实候选标题交给已配置的聊天 API 判断，选中后自动播放。
- 更自由的表达由聊天模型理解，例如“今天有点累，挑点音乐陪我歇一会儿”。模型使用 `music_pick` 提交选歌请求，程序再提供候选。
- 指定歌名仍走原有精确/正则搜索；“拿麦唱歌”“唱一下”仍是单独的表演动作。

默认随机选择优先使用当前音源的歌单，本地当前歌单没有可播放文件时再使用其他本地歌曲或 B站链接。按偏好选歌可从本地和 B站候选中选择；可以指定音源或准确的本地歌单名称。每个 B站链接仍算一个曲目。

随机或自主挑歌会尽量避开当前歌曲和本次运行中最近选择的歌曲；仅剩一首时可以重复。原有顺序、随机、循环模式不会因挑一首歌而改变。

## 执行与反馈

- 空歌单或本地文件失效时说明实际原因，不假装已经播放。
- AI 只能返回真实候选的编号，不能提供文件路径、下载网址或自造歌曲。
- 最多发送 60 个候选的标题、来源和歌单名称，不发送本地路径、视频网址或音频。风格选择基于标题等信息，不代表分析过歌曲。
- 取消、切换角色、离开陪伴模式或手动改变歌单/播放状态后，迟到选择不再执行。
- 成功回复包含实际选中的歌名，说明“正在准备播放”；B站加载、验证或音频错误仍由播放器显示实际状态。
- 这是本轮用户要求下的自主选择。空闲主动聊天仍按原开关运行，不会因此突然播放音乐或开启工作模式。

## 接口

`music_random`：可选 `source`（`local` / `web`）和 `playlist`（本地歌单名称）。

`music_pick`：可选 `preference`（风格/心情/场景）、`source`、`playlist`。所有字段只接收 1～160 字符的文本；不接受额外参数，也不会把参数作为文件路径、下载网址或代码执行。

例：`[动作:music_pick {"preference":"轻松一点，适合睡前","source":"local"}]这就从歌单里挑一首。`
